# 打包验证流程

每次发布均应记录构建环境、提交版本、exe 哈希和实际结果，不预填“全部通过”。

1. 检查 `git status`，确认真实配置、`.env`、`dist/` 和用户录制数据未被提交。
2. 用构建所用的 Python 运行 `python -m unittest discover -s CyberMiao_App/tests -v`。
3. 运行 `python CyberMiao_App/build.py --debug`。检查构建日志、`warn-CyberMiao.txt` 和自动生成的运行检查报告。
4. 双击调试版，在 GUI 填写测试 Key、保存、启动，访问 `/api/health`；验证停止、重启、托盘和退出。测试 Key 不具备真实云端能力。
5. 运行 `python CyberMiao_App/build.py` 构建无控制台正式版。正式版也必须通过相同的自动运行检查。
6. 对正式版重复 GUI 关键流程，确认没有后台异常，退出后端口释放且无遗留服务进程。
7. 在发布说明中列出实际未验证范围，包括真实 DashScope 鉴权、ESP32 硬件、其他 Windows 机器与网卡环境。

`--check-runtime <报告路径>` 会在隔离目录检查 OpenCV 编解码、MediaPipe 模型推理、服务进程、HTTP、WebSocket、停止和重启。检查从不同工作目录运行，不使用正式配置，也不调用云端 API。

发布包必须保留 `BUILD-INFO.json` 和用户说明。性能、启动耗时和跨机器兼容性只有经过专门测量或验证后才能写入结论。

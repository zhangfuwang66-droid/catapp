# 同款设备升级与功能边界

同款猫、鹿可以共享共同功能源码，分别编译自己的产品类型；每台保留设备编号、独立凭证、Wi-Fi、表情资源和原有性格档案。用户账号、记忆与个人资料库保存在后端，设备重启或更新主程序不要求重新建立用户数据库。

## 三类材料各自负责什么

- **共同固件包**：麦克风/扬声器、摄像头、舵机、显示、Wi-Fi 配网、账号配对、HTTPS/WSS、播放缓冲与 USB 诊断。猫和鹿只共享实现，不共享身份前缀与凭证。
- **每台设备自己的材料**：完整 Flash 私密备份、旧程序来源、实际接线、原表情兼容性、稳定设备编号、原人格快照和后台引用。其它设备的备份不能作为这台设备的恢复文件。
- **后端和用户数据**：登录绑定、语音开关、模型 Key、聊天摘要/记忆、资料上传与检索。是否生效以部署版本和账号配置为准；固件编译成功不代表这些服务已验收。

原表情位于文件系统，主程序升级不写该区域，并在启动前逐段验证。原性格可能来自服务器或历史配置，必须有独立档案并确认后端实际采用；它不能靠设备类型、资源未变化或一个引用字符串推断。

## 当前源码具有的能力

- 文字/语音对话、实时对话、视觉上下文、翻译与复述；模型兼容性、地域及账号额度取决于实际模型设置。
- 表情与舵机动作、音频缓冲播放、网络与播放诊断。
- 无可用 Wi-Fi 时通过独立热点配网，已保存网络开机重连；换网与账号身份分开处理。
- 独立设备身份、账号配对与云端 HTTPS/WSS；未绑定或凭证无效时限制业务连接。
- 后端聊天记忆、空闲摘要、个人资料库与检索；用户资料按账号权限隔离。

天气、实时日期/时间以及其它在线工具需要对应后端工具和调用路由，不能把模型猜测当成实时查询。应逐项确认是否已在目标服务器部署、调用是否真实执行、错误是否如实返回，再列入交付完成清单。

## 下一台同款设备怎么做

1. 核对 PCB 与所有外设接线、ESP32-S3/8MB Flash/8MB OPI PSRAM、猫或鹿类型，不仅看芯片型号。
2. 只读识别，保存这台设备的完整备份；未知原程序先审查，不自动升级。新工具的 `backup` 不要求原固件已经支持身份协议。
3. 从可信配置保存原人格快照，确认同一设备的后台档案；来源不明时保留待核对，不能统一改成小猫性格。
4. 复用已经审查、固定 SHA-256 的同类型构建包。工具的 `upgrade` 要求设备已经具备当前 USB 身份/诊断协议；原厂固件的首次适配另行办理。
5. 默认先输出计划；获准后每台独立备份、只写主程序、校验保护区，再检查重启后的身份、配置与资源。
6. 验收原屏幕/表情、摄像头、语音、舵机、配网、绑定、原人格及后端能力。只有这些实物和云端项目也完成，才算这台设备交付完成。

工具与可执行命令见 [统一固件工具](../firmware/tools/README.md#同款设备的统一固件工具)。复用构建包可以省去每台重新编译；每台完整备份与核验仍保留，不承诺未经测量的烧录用时或成功率。

# 打包验证流程

每次发布均应记录构建环境、提交版本、exe 哈希和实际结果，不预填“全部通过”。

1. 检查 `git status`，确认真实配置、`.env`、`artifacts/` 和用户录制数据未被提交。
2. 用构建所用的 Python 运行 `python -m unittest discover -s desktop/tests -v`。
3. 运行 `python desktop/build.py --debug`。检查构建日志、`warn-CyberMiao.txt` 和自动生成的运行检查报告。
4. 双击调试版，在 GUI 填写测试 Key、保存、启动，访问 `/api/health`；验证停止、重启、托盘和退出。测试 Key 不具备真实云端能力。
5. 更新 `desktop/VERSION`，确认已安装 Inno Setup 6，运行 `python desktop/build.py` 构建正式版。正式版必须通过本地运行检查后才会生成安装器；传入 `--version` 时必须与版本文件一致。
6. 确认 `artifacts/release/` 中同时存在 `CyberMiao-Portable-x64.exe` 和 `CyberMiao-Setup-x64.exe`，并核对 `BUILD-INFO.json` 里的文件大小和 SHA-256。
7. 安装并启动安装版，确认开始菜单入口可用；卸载后确认 `%LOCALAPPDATA%\CyberMiao` 中的用户数据仍保留。再对便携版重复 GUI 关键流程，确认退出后端口释放且无遗留服务进程。
8. 在 GitHub Release 只上传两个 x64 exe；源码 ZIP 和 tar.gz 由 GitHub 自动提供。发布说明列出真实未验证范围，包括真实 DashScope 鉴权、ESP32 硬件、其他 Windows 机器与网卡环境。

`--check-runtime <报告路径>` 会在隔离目录检查 OpenCV 编解码、MediaPipe 模型推理、服务进程、HTTP、WebSocket、停止和重启，以及实际界面的资源加载、配置保存、页面切换与按钮启停。检查从不同工作目录运行，不使用正式配置，也不调用云端 API。

发布包必须保留 `BUILD-INFO.json` 和用户说明。性能、启动耗时和跨机器兼容性只有经过专门测量或验证后才能写入结论。

每次构建的详细日志和检查报告保存在已忽略的 `artifacts/`。面向用户的更新内容、验证范围与已知限制写入对应的[中文版本公告](发布流程.md)，不要把某次本机的通过记录当成后续版本的验收结果。
